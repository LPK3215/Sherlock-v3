# 夏洛克业务方向与能力包路线

## 1. 本次共识

夏洛克不是一个只提供视频通话的产品,也不是一个只服务单一行业的智能体。它是建立在 Sherlock-v3 通用 Agent 基座之上的多领域 AI 助手平台。

视频、语音、文字、图片和文档是用户与夏洛克交互的入口。真正的业务价值来自夏洛克根据用户、场景和问题,选择合适的知识、记忆、工具、Skill、数据库和外部服务,完成回答或业务操作。

因此,第一阶段解决的是系统级能力:

- 多模态输入和实时语音、视频、屏幕交互
- Agent 生命周期、会话历史、运行事件和持久化
- Tools、Skills、MCP、SubAgent 和审批机制
- 知识库、数据库、工作区和记忆能力
- 管理端、权限体系和运行监控

后续工作的重点不再是无限堆叠通用底层能力,而是围绕个人业务逐步建设领域能力包。

## 2. 核心产品判断

### 2.1 技术架构做宽

Sherlock-v3 核心系统保持通用,为不同领域提供统一的:

- 多模态对话入口
- Agent 调度和工具调用协议
- 知识库和文件处理能力
- 记忆、历史和事件记录
- Skills、MCP、数据库连接和 SubAgent
- 用户、管理员和权限边界

### 2.2 第一批产品能力做细

夏洛克长期可以覆盖学生、法律、职场、程序员、企业等多个领域,但不应一开始把所有领域的知识和工具混在一个 Agent 中。

第一批能力应选择一个明确的人群和高频场景做深,跑通从输入到业务结果的完整闭环,再复制能力包模式扩展到其他领域。

最终原则是:

> 品牌上做宽,产品上做窄,架构上做成可扩展的领域能力包。

## 3. 领域能力包模型

每个领域作为夏洛克平台上的一个独立能力包,而不是修改核心系统来兼容所有业务。一个领域能力包可以包含:

- 领域系统提示词和 Agent 配置
- 按人群、年级、专业或场景划分的知识库
- 业务数据库表和数据访问工具
- Tools:完成一个明确动作
- Skills:编排一组完整业务流程
- MCP 或第三方 API 连接
- 记忆写入规则和历史查询规则
- 用户角色、权限和审批规则
- 推荐的实时视频、图片、语音交互流程

示例能力包:

```text
夏洛克
├── 学生学习助手
├── 法律顾问
├── 职场助手
├── 程序员助手
└── 企业业务助手
```

能力包之间共享 Sherlock-v3 核心系统,但知识、工具、数据和权限默认隔离,避免无关内容互相干扰。

## 4. 首个验证方向

首个业务方向暂定为“学生学习助手”,但仍需要进一步收窄到具体年龄段、学科或学习场景。推荐优先选择以下其中一种:

- 小学高年级到初中阶段的数学学习
- 初中生的综合学习和错题辅导

首个版本的目标不是覆盖所有学生和所有学科,而是验证一条稳定闭环:

```text
文字 / 语音 / 摄像头 / 图片 / 文档
    -> 识别问题和学习上下文
    -> 检索对应知识
    -> 分步骤讲解和追问
    -> 保存错题与学习记录
    -> 更新薄弱知识点
    -> 推荐练习或下一步学习任务
```

可以支持的典型场景包括:

- 拍照或摄像头展示题目并请求讲解
- 语音描述不会做的步骤
- 上传课本、试卷或学习资料
- 根据学生年龄、年级和水平调整解释方式
- 检查答案并解释错误原因
- 保存错题并查询历史错题
- 生成相似题和针对性练习
- 总结薄弱知识点
- 制定和查询学习计划
- 通过实时视频继续追问当前题目

## 5. 学生学习助手的首批能力

### 5.1 业务数据

建议使用结构化数据库保存:

- 学生资料:年级、学科、学习目标和当前水平
- 题目记录:题目内容、来源、学科、知识点和难度
- 错题记录:错误答案、错误类型、分析结果和复习状态
- 知识点掌握情况:已掌握、薄弱、待复习
- 学习计划:任务、截止时间、完成状态
- 学习事件:学习会话、练习、复习和阶段性总结

### 5.2 知识库

学习资料应放入知识库,并通过元数据隔离:

```text
领域: 学生
年级: 初中
学科: 数学
教材: 教材版本
章节: 一元一次方程
难度: 基础
类型: 概念 / 例题 / 练习 / 易错点
```

这样检索时可以优先使用正确的年级、学科、教材和章节,而不是把所有资料放在一个无边界的知识库中。

### 5.3 首批 Tools

Tools 用于完成明确、可验证的动作,例如:

- 识别题目图片
- 解析题目
- 检查学生答案
- 保存错题
- 查询错题
- 更新学习进度
- 查询学习进度
- 记录学习事件
- 生成相似题
- 总结薄弱知识点

涉及新增、修改或删除业务数据的 Tool,应定义参数校验、用户权限、审计记录和必要的人工确认规则。

### 5.4 首批 Skills

Skill 用于编排完整流程,例如:

- 拍照讲题 Skill
- 错题整理 Skill
- 考前复习 Skill
- 每日学习计划 Skill
- 薄弱知识点补强 Skill
- 根据错题生成练习 Skill

例如“错题整理 Skill”可以依次完成:

1. 读取图片或文档
2. 识别题目和学生答案
3. 判断学科、知识点和难度
4. 分析错误原因并给出讲解
5. 保存错题
6. 更新薄弱知识点
7. 推荐相似练习

## 6. 数据边界

不同类型的数据应进入不同的存储位置,不能把所有内容都写入长期记忆:

| 数据类型 | 适合保存的内容 |
| --- | --- |
| 会话历史 | 具体问题、回答和对话上下文 |
| 长期记忆 | 用户偏好、长期目标和稳定的学习特点 |
| 业务数据库 | 错题、知识点、学习进度、计划和任务 |
| 知识库 | 教材、课程、题库、讲义和参考资料 |
| 工作区文件 | 用户上传的原始资料和 Agent 生成的文件 |

“从什么都不会开始逐渐成长”的设想可以通过用户档案、长期记忆、结构化学习记录和知识库共同实现,而不是依赖单个 `MEMORY.md` 文件承载全部信息。

## 8. 验收标准

详细的领域画像、场景依赖、工具清单、数据边界和新增领域登记模板见[《夏洛克领域能力登记册》](2026-08-04-sherlock-capability-registry.md)。新增领域必须先登记再实现,并明确区分已实现、已复用、规划中、条件启用和暂不需要。

第一套业务能力包完成的标准不是“增加了很多工具”,而是用户可以从任意支持的入口提出一个真实问题,夏洛克能够:

1. 理解用户和当前场景。
2. 选择正确的知识库、Tool 或 Skill。
3. 给出符合用户水平的结果。
4. 在允许的权限范围内保存或修改业务数据。
5. 在历史记录中查询到本次过程和结果。
6. 对需要确认的操作先请求用户批准。

首个闭环稳定后,再使用相同的能力包方法增加法律顾问、职场助手或其他领域,不需要推翻 Sherlock-v3 核心系统。
