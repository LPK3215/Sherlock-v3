# 夏洛克领域能力登记册

## 1. 文档目的

这份登记册是夏洛克新增领域能力时的开发依据。每个领域先登记“要解决什么问题、需要哪些资源、哪些动作需要工具、哪些数据需要持久化”,再实现和验收。

登记册不要求提前穷举一个领域的全部知识和全部场景,只登记当前产品阶段要覆盖的常见能力和明确依赖。没有登记的能力不视为已经实现,没有必要的依赖不为了形式强行创建。

## 2. 统一架构

```text
用户自然语言和多模态输入
    -> 夏洛克识别任务与上下文
    -> 按需读取相关 Skill
    -> 只使用该场景需要的 Tool、知识库、数据库或 MCP
    -> 经过权限和确认规则
    -> 夏洛克以统一身份回复或完成动作
```

夏洛克是唯一的总智能体。领域 Skill 是方法、流程和约束;Tool 是明确动作;知识库是资料来源;数据库是结构化业务状态;MCP 是外部系统连接。领域能力不能替换夏洛克的身份,也不能自行扩大权限。

## 3. 能力状态

| 状态 | 含义 |
| --- | --- |
| 已实现 | 代码、注册、依赖和基础测试已经存在,可以进入运行时验证 |
| 已复用 | 不需要新增领域代码,使用 Yuxi 现有入口或通用工具 |
| 规划中 | 已确定产品需要,但尚未实现或尚未完成真实场景验收 |
| 条件启用 | 只有配置对应知识库、MCP、模型或外部服务后才可用 |
| 暂不需要 | 当前场景不需要该类资源,不创建空工具或空数据表 |

## 4. 平台通用能力

这些能力属于夏洛克和 Yuxi 基座,不重复复制到每个领域:

| 能力 | 作用 | 状态 | 领域使用方式 |
| --- | --- | --- | --- |
| 统一身份 | 始终以夏洛克身份回答,领域 Skill 不创建新 Agent | 已实现 | 所有领域共享 |
| 文本对话 | 接收自然语言并流式回答 | 已复用 | 所有领域共享 |
| 图片和文档输入 | 读取用户上传的图片、文档和解析结果 | 已复用 | 按任务决定是否使用 |
| 摄像头和屏幕帧 | 从实时通话获取当前视觉输入 | 已复用 | 适合拍题、合同展示、现场分析等场景 |
| 语音输入输出 | STT、TTS 和实时语音交互 | 已复用 | 作为输入渠道,不单独定义领域身份 |
| Skill 加载 | 按运行时可见范围读取 Skill,展开依赖并记录激活状态 | 已实现 | 领域 Skill 按需激活 |

| 权限和审批 | 控制用户数据访问及写入、修改、删除、外发动作 | 已复用 | 领域定义操作级规则 |

## 6. 法律事务领域

法律领域先登记为可扩展能力包,目标是覆盖常见法律信息处理和合同辅助场景,不是把完整法典一次性塞进提示词或数据库。

### 6.1 领域画像

| 项目 | 定义 |
| --- | --- |
| 领域名称 | 法律事务分析助手 |
| 统一身份 | 夏洛克,不是律师身份,不替代持证专业意见 |
| 核心目标 | 理解用户事实和文档,发现问题,检索依据,整理风险和下一步行动 |
| 主要输入 | 自然语言、合同、通知、图片、扫描件、录音转写、视频中展示的文档 |
| 方法原则 | 区分事实、用户主张、资料依据和模型分析;需要时引用来源并说明时效性 |
| 资料原则 | 优先官方、用户提供或明确授权的资料;不把不确定内容伪装成确定法律结论 |
| 高风险边界 | 诉讼时效、重大财产、刑事、人身安全等情形应提示尽快咨询专业人士 |

### 7.1 领域画像

| 项目 | 定义 |
| --- | --- |
| 领域名称 | 视觉观察与万物识别能力包 |
| 统一身份 | 夏洛克,不是植物、动物或商品鉴定 Agent |
| 核心目标 | 观察当前图片、摄像头帧或屏幕内容,给出候选识别并按需核验 |
| 输入 | 图片、实时视频帧、共享屏幕、文档和用户问题 |
| 方法原则 | 先看当前画面,区分直接观察、候选推断、资料核验和不确定性 |
| 资料原则 | 只在需要时查询知识库或搜索,不伪造全量物种/商品资料库 |
| 数据边界 | 只保存用户确认的结构化观察摘要,不保存原图、不逐帧入库 |

### 7.2 场景与依赖登记

| 子模块 | 场景 | Skill | Tool | 知识源 | 数据库 | 权限与确认 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |

| 候选识别 | 识别植物、动物、物品、商品或设备 | `visual-identification` | 当前多模态输入 | 可选 | 不需要 | 只读分析,不承诺专业鉴定 | 已实现/已复用 |
| 资料核验 | 用户要求来源或结果不确定 | `visual-research` | `query_kb`、`open_kb_document`、`search_file` | 用户可访问知识库 | 通常不需要 | 仅访问授权资料 | 条件启用 |
| 观察历史 | 用户要求保存或查询观察摘要 | `visual-observation` | `save_visual_observation`、`list_visual_observations` | 不需要 | `visual_observations` | 保存前明确确认,查询仅当前 UID | 已实现 |

### 7.3 三个 Skill 与边界

- `visual-observation`:总流程和保存规则,不自动写入记录。
- `visual-identification`:描述画面特征、候选结果和置信度,不替代专业鉴定。
- `visual-research`:按需使用知识库工具核验来源,不把资料库内容冒充画面事实。

危险、医疗、食品安全、毒性和设备安全相关判断只提供谨慎信息,必要时建议专业或官方渠道确认。

### 8.3 三个 Skill 与边界

- `career-work`:负责工作信息整理、行动项提取和确认式记录。
- `career-document`:负责职业文档事实提取和表达建议,不编造履历。
- `career-planning`:负责目标拆解和复盘建议,不替用户作出职业承诺。

劳动合同、劳动争议或其他法律问题交给法律能力按需处理;职业领域不会复制法律知识库或法律工具。

| 前端工具状态事件 | 复用通用 `tool_call`、`tool_call_delta`、`tool-started`、`tool-finished` 事件链路;职业工具名称由注册表和 ToolCall 载荷传递,不新增领域专用 UI | 通过代码链路和事件归一化测试 |

本阶段仍不宣称真实模型能够对所有职业问题自动识别或替代专业服务;模型自然语言选择 Skill 的质量依赖 Agent 配置、模型能力和实际提示词输入,领域侧已提供清晰的 Skill 描述、依赖和边界。未确认的保存、外部发送和对外承诺仍不得自动执行。

## 9. 新增领域的登记模板

新增志愿填报、编程、职场或其他领域时,复制以下结构填写,不直接复制全部学生领域工具:

1. 领域画像:服务对象、目标、输入、边界和统一身份。
2. 子模块清单:每个模块对应的常见场景和用户结果。
3. 场景依赖表:输入、Skill、Tool、知识源、数据库、MCP、权限和状态。
4. 数据边界:哪些内容进入会话历史、长期记忆、业务数据库、知识库或工作区。
5. 依赖验收:必需 Tool、知识库、数据库和 MCP 在启用前必须存在且可访问。
6. 跨领域验收:单领域问题、连续切换问题和同时涉及多个领域的问题。

## 10. 开发准入规则

每个新增能力在进入系统前必须完成:

- 在本登记册中明确场景和依赖。
- 为必需 Tool、数据库、知识库和 MCP 指定真实实现或明确标记条件启用。
- Skill 描述清楚适用场景、禁止事项、确认规则和工具依赖。
- 工具注册后通过工具注册测试和最少一条真实流程测试。
- 写入、修改、删除、发送和外部副作用操作具备权限与确认测试。
- 不把领域资料、用户隐私或业务状态混入夏洛克核心提示词。
- 验证新能力与已有能力共存,且回复身份仍然是夏洛克。

## 11. 当前结论

夏洛克采用“通用总智能体 + 按需领域能力包”模式。目标不是让一个模型在每个专业领域都达到垂直产品的极限深度,而是提前准备常见场景所需的高质量能力,在用户提出问题时动态读取和调用正确资源。专业深度通过更窄的 Skill、边界清楚的知识库、必要的业务数据库和专用工具逐步增强,而不是通过无边界堆叠工具和资料获得。
